Engineering highlights

Problems I've solved

Real problems from production apps, what I built, and what changed.

Offline-first work sync

Problem
Technicians record check-ins, photos and completed work on sites with no signal.
What I built
A Hive-backed outbox stores every action against the visit it was recorded on, then replays it in stages with a progress bar when the network returns.
Result
Work posts to the right visit even on multi-day jobs; I fixed a bug where replay used to attach a day's work to the wrong visit.
FlutterBLoCHiveDio

Evidence-grade photo pipeline

Problem
Clients need proof of where and when work was done.
What I built
A camera service compresses each shot and stamps it with time, GPS and a reverse-geocoded address, keeping originals private and uploading only the final JPEG.
Result
Photos double as audit evidence in service reports and invoices.
Fluttercamerageolocator

Race-safe job claiming

Problem
Shared jobs were being claimed by two people at once.
What I built
Replaced a read-then-write path with one conditional update under a per-job Postgres advisory lock; the loser gets a clear 409, and an owner re-checking in is a no-op for offline replay.
Result
No more double-assigned visits.
NestJSPostgreSQLPrisma

Token refresh under load

Problem
Many requests failing with 401 at once each tried to refresh the session.
What I built
A refresh coordinator in the Dio client lets the first 401 refresh and makes the rest wait for it, then retries them with the new token.
Result
One refresh per expiry, no random logouts.
DartDioInterceptors

Multi-tenant platform

Problem
Each customer company needs its data fully isolated.
What I built
Schema-per-tenant PostgreSQL with a Prisma client per tenant, plus a queue-driven onboarding job that creates the schema, seeds defaults and activates the account.
Result
New tenants go live without manual setup.
PostgreSQLPrismaBullMQRedis

WhatsApp service intake

Problem
Customers message on WhatsApp; staff used to retype every request.
What I built
A Redis-backed conversation state machine on the Meta Cloud API turns messages, photos and location pins into service requests, matches the sender to a client by phone, and caps spam.
Result
Requests reach the office with no manual entry.
NestJSRedisWhatsApp API

AI assistant with real tools

Problem
Office staff wanted to ask questions and create records in plain language instead of clicking through screens.
What I built
A streaming chat service on the Vercel AI SDK, plus an MCP server that exposes the platform's own APIs (clients, contracts, quotations, tasks) as tools the model can call, with a preview-then-confirm step before anything changes.
Result
Users get answers and drafts inside the dashboard, and every write still goes through the same permissions as the app.
Vercel AI SDKMCPLLM tool callingSSE

Web apps people work in all day

Problem
Operations teams and their customers each needed their own web app on the same data.
What I built
The operations dashboard and a separate client portal in React 19 with TanStack Router, React Query, Zustand and Tailwind, sharing typed API clients generated from the backend's DTOs.
Result
Two web apps on one API, with schema drift caught in CI before it reaches users.

Fast sites at the edge

Problem
The product needed a marketing site, docs, and a public booking form that strangers could use safely.
What I built
A Next.js marketing site, a static docs site, and a booking form served from Cloudflare Workers, with layered spam limits and photos re-encoded server-side to strip location data.
Result
Fast public pages, and a form that can't be abused to flood the system.
